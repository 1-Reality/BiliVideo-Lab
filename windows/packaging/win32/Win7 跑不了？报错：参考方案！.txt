Win7 跑不了？报错：参考方案！

【报错长这样】
  pilibro.exe - 无法找到入口
  无法定位程序输入点 GetHostNameW 于动态链接库 WS2_32.dll 上。

【为什么】
  GetHostNameW 是 Windows 8 才加进系统的功能，Win7 自带的 WS2_32.dll 里没有。
  这跟 VC++ 之类的运行库无关，运行库装得再全也补不上，因为缺的是 Windows 系统文件本身。
  PiliBro 基于 Flutter，Flutter 官方只支持 Win10 及以上，所以引擎会直接调用 Win8、Win10 才有的系统功能。
  64 位版在 Win7 上也一样起不来。

【参考方案：VxKex】（适用于Win7）
  VxKex 是第三方工具，专门给 Win7 补上 Win8、Win10 新增的系统功能，很多只支持 Win10 的软件靠它在 Win7 上运行。
  1. 系统需要是 Win7 SP1，建议先装好 KB2533623 和 KB2670838 两个补丁。
  2. 从 GitHub 发布页下载安装：https://github.com/i486/VxKex
  3. 右键 pilibro.exe → 属性 → VxKex 选项卡 → 勾选启用。
  4. 双击 pilibro.exe 运行。

【参考方案：VxKex-Next】（若前者安装失败，或使用Win8/8.1）
  https://github.com/YuZhouRen86/VxKex-NEXT

  注意：这是第三方方案，我们没法保证所有功能可用；但是这不是高考，就算错一道题不是不可挽救，这也不是工厂会爆炸；这种很显然的东西还是自己实测最有效，没必要蹑手蹑脚。

【顺便说明】
  这是便携版：解压即用，不写注册表，删掉文件夹就卸载干净。

  ⚠️ 请检查您使用的系统 位宽 是否正确。只有压缩包文件名里含“64”的才是适用于64位版本的，这个是编译好的，性能显著更优。

  🛑 32 位是迫不得已支持，采用的JIT运行时编译：编译只进内存，系统最多只会缓存热点函数，每次启动仍需编译；使用起来可能刚启动会有掉帧情况，启动较慢！不过MPV底层本身是编译好的。
  
  🚨 64 位系统上建议用 64 位版，速度更快，尤其是首屏启动也快很多，并且相对CPU发热更低，续航损耗更小。
